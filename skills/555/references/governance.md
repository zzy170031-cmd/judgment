# Unified Five-Agent Governance

Read only when the user explicitly requests the named council/closed-loop
workflow or a current project rule requires it. Ordinary Judgment audits keep
dynamic domain roles. Governance shares the same frozen packet, issue tree,
finding register, evidence standard, and final decision owner.

The compatibility name `five-agent-closed-loop-governance` and the legacy name
`five-agent-governance` route here through Judgment. They do not maintain a
second execution contract.

## Start with real identities

Record checkpoint, selected scope, authorization, requested/started/failed
agents, real identities, and available concurrency. Create Maxwell, Dirac,
Parfit, Wegener and Popper as separate read-only agents; the host's active cap
governs batching. Do not require all five to run simultaneously. Claim full
council coverage only after all five supplied their required work; unavailable
or failed seats mean partial coverage, not simulated replacements.

Read-only reviewers cannot delegate, edit, install, send externally, or accept
on the user's behalf. The root Controller owns decomposition, evidence
acceptance, actual authorized execution, and the user-facing recommendation.
Five seats, self-review passes and discussion rounds are not J challenge units.

## Select the lightest sufficient council scope

| Scope | Use |
|---|---|
| Full Council | A requested project startup, material architecture decision or phase/release review |
| Fast Gate | A bounded checkpoint inside an already governed project |
| Closed Loop Council | Authorized correction work needs repeated validation and independent recheck |

These checkpoint names do not revive retired general Judgment runtime modes.
Preserve an explicit J-level. Otherwise select the smallest sufficient level
for the material decision using the existing router. Count only units with the
complete blind-answer, opposing challenge and independent verification record.

## One chain, one evidence record

1. **Maxwell** establishes the real need, scope, priorities, success evidence
   and unresolved decisions. Discovery expands understanding, not authority.
2. **Dirac** proposes a concrete structure, interfaces, dependencies, sequence,
   alternatives and rollback within that brief.
3. **Parfit** examines user needs, accessibility, tests, operations, consistency
   and practical acceptance. Specialize these questions to the chosen Profile.
4. **Wegener** reviews the first three positions using two distinct passes:
   assumptions/dependencies, then failure/handoff conditions. Follow with two
   self-checks for omitted counterexamples and scope/evidence inflation.
5. **Popper** challenges the integrated path through three falsification lenses:
   a triggerable failure, applicability to actual use, and missing evidence or
   premature phase advancement. Return a recommendation with exact allowed
   action and stop conditions.

Take blind positions before sharing other conclusions. Subsequent passes use
the single Red/Blue phase and evidence protocol: each claim needs a distinct
question or new evidence, not repeated debate to fill a quota. Self-review
never supplies independent verification of its own finding. Popper's verdict
is a council recommendation; the Controller verifies it against current
evidence and the real human decision/approval boundary.

## Closed-loop additions

**Core Challenger** tests whether the result and proposed repair are reasonable,
useful, applicable, and exposed to major unexamined risks. It accepts or rejects
the narrowed repair scope and later checks semantic repair rather than removed
symptoms. If this role would verify its own proposal, assign another fresh seat.

**Audit Specialist** joins for evidence-sensitive tests, Git/staging ownership,
release, packaging, artifacts, cleanup, or gate integrity. It verifies changed
scope, exact commands/results, evidence identity, independence and cleanup.
Do not add it to every ordinary semantic judgment. It cannot stage, commit,
publish, or weaken validation under an audit-only packet.

Additional seats run in batches under the live cap. Existing specialist work
may satisfy an equivalent duty only when its evidence path and independence
are preserved and recorded. Do not rename the same conversation as a fresh
independent seat or count a detector as an agent.

Use [repair and recheck](repair-and-recheck.md) for the shared bounded cycle.
`/goal` is optional and requires an explicit user request/standing authority
for that goal, a Core-accepted narrow scope, and an available host capability.
An ordinary repair request does not create a persistent goal. A goal executes
repairs; it cannot approve a product, publication or release.

## Verdict mapping

| Council verdict | Judgment interpretation | Allowed next action |
|---|---|---|
| PASS | go within evidenced scope | Only the named already-authorized next step |
| PATCH | conditional-go for bounded repair | Fix the identified items; no final acceptance yet |
| WAIT | blocked / evidence insufficient | Obtain the named evidence or dependency |
| NO | no-go | Stop the rejected path and explain the alternative |
| ESCALATE | user-decision | Present the real unresolved human decision |

Open blockers, missing decisive evidence or an unfulfilled required validator
cannot map to PASS. A role's acceptance never grants missing execution
authority. Shared audit rules and project-specific gates outrank a label.

## Conditional record fields

Add to the common audit record only when applicable:

- checkpoint and scope-selection reason;
- boot/coverage status and real identities for five seats;
- each blind position, Wegener passes/self-checks and Popper's challenges;
- Core scope decision and post-repair challenge;
- Audit Specialist's ownership/evidence/cleanup record when active;
- repair authority, allowed/forbidden scope, validation, progress and stop;
- goal authority and actual goal id only if one was explicitly created;
- requested/completed J coverage and the one evidence-bounded verdict.

Use actual project validators. Historical case counts, a particular desktop
shell, an old project stage or an old resource-health threshold are not
universal gates. Read [integration sources](integration-sources.md) only for
maintenance/provenance.
