# Authorized Repair and Targeted Recheck

Read when the user has already authorized implementation, correction or a
closed-loop task. A read-only audit still ends at an executable plan. Existing
specific authority persists; do not ask again solely because a new audit
reference was loaded.

## Freeze a repair packet

Bind the current target identity, findings and affected Q ids; allowed files,
fields and commands; preserved content/behavior; baseline/rollback; independent
acceptance evidence; and meaningful stop conditions. Distinguish preexisting
dirty work from this task. Do not stash, overwrite or clean someone else's work
to manufacture a clean baseline.

The executor may edit only the authorized target. Reviewers remain read-only.
Installation, sending, publishing, production access, destructive work and
goal creation each need actual authority for that action. This reference adds
no permission and no mandatory new approval when the user already supplied it.

## Work to closure

1. Select the evidence-supported smallest correction, with owner and rollback.
2. Repair within scope and run the relevant real validator or interaction.
3. Recheck affected findings/Q units and preservation boundaries using someone
   other than the finder/executor for independent acceptance.
4. Preserve the before/after target identity, exact evidence, disposition and
   remaining unknowns. No-op, waived, ignored and false-positive are not fixed.
5. Continue authorized repair while each round makes observable progress and
   the remaining issue is testable within scope. Do not rerun the whole J-level
   for ceremony or count rounds as more assurance.

In an invoked council use its Core Challenger and conditional Audit Specialist.
In a normal domain audit use the equivalent necessary independent roles; a
five-agent council is not mandatory for every edit.

## Stop honestly

Stop on a decisive blocker, new human/product judgment, scope/authority change,
required environment failure, exhausted agreed budget, or repeated lack of new
evidence/progress. A still-failing or unexecuted required check stays open. Keep
the artifact and evidence so the user can resume; do not silently change the
acceptance criterion, relax tests or convert a timeout into success.

A changed goal, core proposal, material criterion or material risk boundary
requires a new frozen audit. A bounded correction receives a new seal, updates
affected units and their actual evidence, and records which unaffected evidence
remains valid. Unexplained drift stops acceptance; it is not a tracked repair.
If a required named J audit cannot be completed independently, report achieved
coverage and the remaining gap.

For audit-only clarification, one bounded targeted evidence recheck is enough;
without new evidence return the unknown rather than debating again. Authorized
implementation may need multiple correction cycles, with the same progress and
scope stops above.
